# Methodology Selection Justification

SariwaBa will use Scrum as its primary methodology. Scrum is an adaptive Agile framework that supports iterative and incremental development. The project's main scope is established, but technical details may change as the team tests image preprocessing, Google authentication, the external ML service, Flutter compatibility, and cloud deployment. Its fixed semester deadline, small team, and need for instructor, adviser, and user feedback favor short, time-boxed sprints.

Waterfall is less suitable because problems discovered late could require major rework. Spiral addresses technical risk but requires formal risk analysis that is excessive for a semester project. The SDLC activities will be repeated across Sprint 0 and five development sprints, with each sprint including planning, requirements, design, implementation, testing, integration, and review.

GitHub branches, code reviews, automated checks, Django migrations, and staged Vercel and Render deployments will support delivery. The team will control scope by protecting the active sprint and placing noncritical changes in the prioritized product backlog.
